# Phase 9 QA: in-process API smoke (2026-11-07)

## Environment
- Throwaway SQLite DB (`qa.db`, outside the repo), never the real `data/fitness_dashboard.db`.
- Data: ~90 days of live **Garmin-only** data (workouts incl. strength; no sleep rows, no Garmin exercise sets), no Whoop.
- No credentials involved: the owner is looked up in the DB and a token is minted in-process.
- Branch `feat/phase9-qa`, HEAD `6c1f179`.

## Method
- `scripts/smoke_api.py` drives the FastAPI app through `TestClient` in-process (no listener, scheduler patched out, no live Garmin/Whoop calls).
- Routes come from the OpenAPI schema, so new GET routes are covered automatically.
- Range routes run at 7, 30, 60 and 180-day windows ending today; `days` routes at the same windows; `/api/trends/{metric}` for every supported metric; workout-id routes for up to 3 real ids (strength workout included for `exercise-summary`/`exercise-sets`).
- Per response: status 200 (or documented 204), valid JSON, no non-finite floats, no placeholder strings (`None`, `NaN`, `undefined`, `null`) in parsed JSON, over 2 s flagged slow.
- Skipped (would touch Garmin/Whoop or non-JSON): `/api/auth/garmin/status`, `/api/auth/whoop/{url,callback,status}`, `/api/account/export`, sync triggers (POST anyway).
- The browser pass is deferred to SJ's session (browser automation was blocked). This smoke check does not replace it.

## Result
- 135 calls, 5 skipped, **0 failures, 0 slow** (slowest call 18 ms).
- Tests: full suite 1040 passed (baseline 1038 + 2 new); `make lint` clean.

## Findings
| # | Severity | Finding | Suggested fix |
|---|---|---|---|
| 1 | Low | `GET /api/readiness/today` returns 204 when there is no data (docstring says so) but the OpenAPI schema lists only 200/422. The smoke tool allow-lists it. | Add `responses={204: {...}}` to the route decorator and drop `ALLOW_204_ROUTES`. |
| 2 | Info | Data gaps limit coverage: no sleep rows and no exercise sets, so sleep and strength-summary routes only exercised their empty paths (all returned 200 with valid JSON). | Verify the populated shapes in the browser, or seed a fixture DB with Whoop and set data. |
| 3 | Info | Whoop-dependent routes (`/api/auth/whoop/*`) and Garmin status were not exercised. | Cover in the browser pass or with mocked probes. |
